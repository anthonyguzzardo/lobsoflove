# CLAUDE_INDEX.md (LobsOfLove database)

Start here. This folder follows the Dealifier db standard (`../Dealifier/db`): own schema (`lol`), table prefixes,
`<table>_id` keys, `dttm_<event>_utc` timestamps, RLS on every table, every change in BOTH a migration and the
canonical files.

## Folder structure

```
db/
├── CLAUDE_INDEX.md              # THIS FILE
├── sql/
│   ├── dbLOL_Tables.sql         # canonical CREATE TABLE for every table (current state, no ALTERs)
│   ├── dbLOL_Security.sql       # GRANTs, RLS policies, helper functions
│   ├── rpc/                     # rpc_<domain>.sql (none yet)
│   └── migrations/NNN_*.sql     # deployable change history; the user runs these in the SQL Editor
├── supabase/
│   ├── config.toml              # exposes the lol schema; per-function verify_jwt (always false, commented)
│   └── functions/read-ink/      # AI handwriting reader (index.ts = HTTP, caps, logging; read.ts = model call)
├── tests/try_read_ink.ts        # tries read-ink's model call directly (costs a few cents)
├── types/database.types.ts      # generated by sync-types.sh, never hand-edited
└── sync-types.sh                # regenerate types + copy into ../src/types
```

## Workflow rules

- Schema change: write `sql/migrations/NNN_<desc>.sql` (idempotent, BEGIN/COMMIT, verification SELECTs) AND update
  `dbLOL_Tables.sql` / `dbLOL_Security.sql` / `rpc/`. The user runs the migration in the SQL Editor; then `./sync-types.sh`.
- New table: RLS enabled + policies in Security, plus explicit `service_role` grants (table and sequence).
- Service/secret keys and the Claude key never go in the app. The app only has the URL and publishable key
  (`EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`).
